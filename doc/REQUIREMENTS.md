# dsh-dbhub-live 需求文档（业务层面）

> 说明：本文只描述业务需求，不涉及实现原理；详细开发说明见 `AGENTS.md`，用户安装使用见 `README.md`。

## 产品定位

为 DSH（DeepSeek Harness）提供数据库操作能力：模型在对话中可以直接查询、搜索、管理数据库连接；支持按工作区配置专属连接，也支持临时连接任意数据库做一次性排查。

## 一、既有功能

### 1. 数据库连接管理
- **支持的数据库**：MySQL、PostgreSQL、MariaDB、SQLite、SQL Server。
- **按工作区配置**：每个工作区可配置并持久化专属连接，一次配置长期复用。
- **三种配置方式**：
  1. 直接填写完整连接串（DSN）；
  2. 按分项填写（类型 / 主机 / 端口 / 账号 / 密码 / 库名）；
  3. 授权扫描项目配置文件（`.env`、`application*.yml`、`docker-compose`、`jdbc.properties` 等），列出候选项供确认后采用。
- **自动发现**：工作区已有 `mise env` 或 `.env`（`DSN` / `DB_*`）时自动识别，无需手动配置。
- **安全约束**：凭据仅存本机用户目录；任何展示/结果中的密码一律打码；扫描敏感文件必须先经用户授权。

### 2. 查询与对象搜索
- **按工作区查询**：在已配置工作区的连接上执行 SQL、搜索数据库对象（表 / 视图 / 列 / 索引 / 函数等），工具名体现工作区身份，多工作区互不混淆。
- **临时连接查询**：对任意未配置的库传入连接串即可查询/搜索（多语句用 `;` 分隔），每次调用独立连接，可同时连多个不同库，便于跨环境对比排查。
- **环境提示**：工具描述和结果中标注目标连接环境（主机/端口/库，密码打码），避免误操作生产库。

### 3. 运行时保障
- 常驻连接复用，提升多次查询效率；空闲一段时间自动回收。
- 首次使用若缺少依赖则自动安装，之后定期自动更新；用户自行安装的版本不受影响。
- 服务异常退出后，下次调用自动恢复，无需人工干预。

## 二、本次新增功能

### 1. 懒加载启动优化
- 插件启动不阻塞 GUI，工具立即可用。
- 环境初始化推迟到首次调用时进行；初始化期间界面提示「初始化中」，查询请求自动等待就绪。

### 2. 插件状态管理
- **启用 / 禁用开关**：关闭后所有 dbhub 相关工具立即返回「插件已禁用」友好提示，无需重启；再次开启立即可用。
- **运行状态**：运行中 / 初始化中 / 异常 三态，实时反映插件可用性。
- **工具数量**：当前已注册工具总数实时展示。
- **错误摘要**：最近一次初始化或运行错误简要信息，异常时展示。

### 3. 浏览器状态卡片（设置在插件的状态面板）
- 展示：运行状态徽章（🟢 运行中 / 🟡 初始化中 / 🔴 异常）、已注册工具数、工作模式（懒加载）、常驻进程状态、最近错误（红色展示）。
- 提供启用 / 禁用开关，即时生效。
- 卡片采用折叠分区（状态 / 配置 / 工作区连接），与其余插件设置面板风格一致。

### 4. 可配置参数（插件配置面板内直接编辑）
- 自动更新间隔天数（0 关闭）、空闲回收时长（分钟）：在「配置」分区编辑后点保存，即时生效并持久化。
- 优先级：用户设置 > 进程环境变量（默认值种子）> 内置默认。
- 自动安装包不进入 UI：由环境变量 `DSH_DBHUB_PACKAGE` 单独控制（默认 `@bytebase/dbhub`）；`DSH_DBHUB_UPDATE_DAYS` 继续作为更新间隔默认值种子。

### 5. 工作区连接管理（插件配置面板内查看与增删改）
- 「工作区连接」分区列出每个工作区 × 环境的连接：工作区名、环境名、打码连接串、来源徽章（已保存 / 自动）。
  - 已保存：经 `dbhub_configure` 或卡片添加持久化于本机。
  - 自动：来自 mise env / .env 自动发现，不持久化、随源文件变化。
- 支持：新增连接（工作区 + 环境名 + 连接串）、修改连接串（对自动项执行修改即转为已保存的手动覆盖）、删除已保存项。
- **同一工作区可添加多个环境**：默认环境 `default`（工具名 `dbhub_execute_sql_<工作区>`），其余环境工具名带 `_<环境>` 后缀，互不混淆。
- 自动配置与已保存配置并存展示；自动发现与实际不符时可手动修改覆盖。
