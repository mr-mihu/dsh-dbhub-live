# dsh-dbhub-live 需求事实记录

> 本文只记录「产品必须满足什么」的**需求事实**（概念层面），不含实现细节；开发实现说明见 `AGENTS.md`，用户安装使用见 `README.md`。
> 版本基线：5.1.0（最近一次正式发布）。5.1 迭代已发布：在 5.0 的零知识凭据 + 一次性进程执行 + dsh 双栈配置页之上，新增环境级只读、手动 SSH 隧道、侧边栏入口开关（与启用状态取交集）、SSH 层独立连通性测试、连接测试分层诊断，以及连接测试快路径。
> 5.2 迭代（测试版 5.2.0-dev.1，正式版目标 5.2.0）：为配置页补上**版本展示与更新检查**（页头当前版本 + 低调的「↑ 可升级到 <latest>」文字链接 + 检查更新按钮；npm registry 为主、GitHub Releases 兜底）与**三套响应式布局**（弹窗 / 宽屏整页 / 手机小屏），把设置收进宽屏页、把只读开关放到连接行内，并补上**桌面端**（desktop profile + 可视化插件页）的安装/更新路径。自 5.2 起插件只支持 **DSH 0.2.1+**（含预发布版），0.1.x 不再支持；宿主版本过旧时只在卡片上给出可见提示，功能照常。
> 该迭代范围：5.1 见第四节 R66、第五节 R67、第十节 R43/R44/R56-R58、第十一节 R49/R68、第十二节 R59-R65/R69 与第十三节 R70；5.2 见第十节 R73-R79；6.0 见第十五节 R80-R83 与第十二节 R84、第十六节 R85。

## 一、产品定位

- R1. 插件为 DSH 提供数据库查询、对象搜索与连接管理能力。
- R2. 连接配置是长期资产，被维护与复用；每一次数据库执行是一次性的、相互独立的劳务行为。

## 二、凭据零知识（安全红线）

- R3. 密码、用户名与完整连接串（DSN）不得出现在模型上下文中的任何位置：工具参数、工具描述、查询结果、错误文本、来源列表均不得包含。
- R4. 模型仅凭「工作区/环境标识（source）」与元数据（数据库类型、主机、端口、库名）完成定位与执行，由插件在宿主侧解析真实凭据并自行执行。
- R5. 凭据的录入与修改必须由人在界面完成（或经授权后由插件仅在本机读取，如项目文件扫描），不得经模型转述。
- R6. 查询因鉴权/连接失败时，系统应给出「凭据或连接信息可能有误」的明确指引，引导用户在界面更新，而非要求模型提供密码。
- R7. 任何底层工具返回的文本在呈现给模型之前必须经过清洗，防止异常路径泄漏密码。

## 三、连接管理

- R8. 支持按工作区配置专属连接，一次配置长期复用。
- R9. 同一工作区可配置多个环境（默认环境与命名环境），彼此独立、可区分、不混淆。
- R10. 连接录入支持三种方式：直接输入连接串、按分项填写、授权扫描项目配置文件后确认；扫描敏感文件必须先经用户授权。
- R11. 工作区已有自动配置（mise env / .env）时可自动识别连接、免手工配置；自动识别项不被持久化。
- R12. 用户可在设置界面查看、新增、修改、删除连接，并可测试连接可达性；测试结果不持久化、仅即时反馈。

## 四、查询与对象搜索

- R13. 模型可通过来源标识执行 SQL，以及搜索数据库对象（表、视图、列、索引等）。
- R14. 支持以分号分隔的多语句 SQL。
- R15. 工具声明数量恒定，不随连接（工作区 × 环境）数量增长。
- R66. 工具集必须**封闭且恒定**：恰好 4 个工具（`dbhub_configure`、`dbhub_list_sources`、`dbhub_execute_sql`、`dbhub_search_objects`），不得按工作区 × 环境注册独有工具；**任何工具都不得声明 `dsn` 参数**（模型一旦把连接串当参数传入，密码就进了模型上下文），模型经 `dbhub_configure` 传入 `dsn` 时必须被明确拒绝并给出指引（延续 R3/R4/R5）。

## 五、执行与运行保障

- R16. 每次执行独立、一次性，不共享长期进程状态；单次执行失败不影响其他执行。
- R17. 支持多任务并发执行，互不影响。
- R18. 支持多个 DSH 实例并存运行，互不影响、无冲突。
- R19. 首次执行缺少依赖时自动安装 dbhub，并按设定间隔自动更新；用户自装版本不受影响。
- R20. 插件可启用/禁用；禁用后所有工具应立即返回友好提示。
- R67. 执行必须按环境选择连接表达方式：未开启只读、也没有隧道的环境继续用 `--dsn`；开启只读**和/或**配置了隧道的环境必须改用**当次生成、用完即弃的 TOML 配置**（`--dsn` 与 `--config` 互斥，且只有 TOML 方言能表达 `[[tools]] readonly` 与 `ssh_*` 字段）。三条硬约束：
  - **生成文件绝不含任何秘密**：连接串与隧道秘密在文件里只以占位符出现，真值随该次子进程的环境传入——因此即使文件残留也不构成泄漏。
  - **只读必须同时声明两条工具**（`execute_sql` 与 `search_objects`）：`[[tools]]` 是白名单而不是补丁，只写一条会让该环境的对象搜索直接不可用（这是 R59「开启只读不得让对象搜索失效」的执行面）。
  - **生命周期**：临时文件只存在于 `$DSH_HOME/storages/dsh-dbhub-live/tmp/`，每次调用结束（**含失败**）都必须尽力删除，插件启动时清扫崩溃残留；不得退化成常驻配置文件、热重载或多源配置（延续 R16）。

## 六、设置与状态界面

- R21. 浏览器端提供配置页：展示启用状态、工具声明数、环境数、最近错误（工作模式作为状态行提示），并支持启用/禁用开关、连接的增删改查、环境改名与连接测试。该页面有**三个入口**且都指向同一页面与同一份状态：设置面板的一级页面（主入口，见 R42）、侧边栏快捷入口（见 R43）与官方「插件」页该行的配置槽（dsh 0.1.6 及以后为 `plugins.row.config`）；后者只是多一个入口，**不得**被当成唯一承载位，也不得替代设置面板里的页面。
- R22. 面板文案与模型侧反馈跟随 DSH 界面语言（中/英）。

## 七、存储与实例隔离

- R23. 配置与凭据仅存本机用户目录，按实例（DSH_HOME）隔离；共享同一主目录的并发实例写入互不破坏（不产生半写文件）。
- R24. 配置持久化失败不应导致崩溃，可降级继续运行。
- R25. 升级或手工修改遗留的旧格式配置应被自动清洗/迁移，未知字段予以保留。

## 八、连接配置交互原则（零打扰优先）

> 本节由 4.0.x 交互优化迭代（探连优先 + 凭据最小询问）沉淀，覆盖用户侧三轮反馈：①可用直接可用、缺什么问什么；②已存连接凭据缺失时应诊断并只补缺失项；③连接信息本身不对或重新描述了目标时应能脱身并按新信息重走判断。

- R26. 对**已配置且校验可用的连接**，配置过程必须自动校验；通过时直接确认「已配置可连通」并提供使用指引，**不要求用户重新输入任何信息**。
- R27. 仅当环境未配置、校验失败或自动试连未成功时才向用户提问；**提问不得索要已知或重复信息**——完整连接串已含密码时，不得再次索取密码。
- R28. 未配置环境下，若已从对话中得知足够的连接事实（类型/主机/库名；SQLite 除外），应**先自动试连**、按结果分流，而不是直接提问：
  - 试连成功 → 按已有信息完成配置并返回可用来源标识，**全程零输入**（免密码连接、信息即用即存）；
  - 试连提示缺凭据 → **只询问缺失项**（账号未知时连账号一起问），其余信息自动沿用，补完即生效；
  - 信息不完整或试连因其它原因失败 → 才提供完整录入方式（输入连接串 / 分项填写 / 授权扫描）。
- R29. 凭据询问必须**说明为什么需要**（试连失败原因），并允许用户表明「连接信息本身不对」从而改走完整录入，避免用户被困在反复补凭据的循环中。**若试连诊断明确指向“空账号被拒”（如 `Access denied for user ''@…`），账号为必填**：凭据询问不得提供「留空（使用空账号）」选择，用户仍提交空账号时应拒绝保存并说明原因，避免把同一个必失败的 DSN 再存回去。
- R30. 用户重新描述的目标（库/主机/端口等）与已存连接不同时，必须**按新描述重新执行判断流程**，不得沿用旧连接的结果。
- R31. 「使用现有连接」是**字面沿用**：不修改、不补填任何缺失字段（如账号/密码）；其文案必须让用户明确这一点，不得暗示会修复缺失项。
- R32. 录入表单与凭据询问都应**预先带入已从对话中得知的字段**，用户只需补充缺失项，避免重复录入。
- R33. 连接保存或被采纳后，应**立即自检连通性**并把结果（可连通 / 失败原因）随回执一并返回，避免用户通过后续尝试才得知失败。
- R34. 连接信息输入界面只提供一个取消入口（由界面自身提供），不得出现重复取消项。

## 九、工作区隔离与来源解析

> 本节由 4.1 迭代沉淀：多工作区各自配置了相似（甚至同名）连接时，模型必须能分辨「这是哪个工作区的哪个环境」，不允许把不同工作区的连接当成同一个使用。

- R35. 每条连接只属于一个工作区；不同工作区的连接是彼此独立的目标，即使连接信息看起来相同也不得视为同一条（不共享、不互相覆盖、不互相替代）。
- R36. 模型侧应优先使用**当前会话工作区**的连接；连接清单必须按工作区分组并显式标出当前工作区。
- R37. 当模型给出的来源标识可能命中多个工作区（同名工作区、同名环境或仅给标题）时，系统必须返回候选清单要求明确指定，**不得按列表顺序或长度猜测**。
- R38. 需要复用其他工作区已配置的连接时，必须先取得用户确认，再由插件在宿主侧把连接**复制**到当前工作区（新建一条属于当前工作区的连接）；凭据与连接串不得因此进入模型上下文，也不得直接用其他工作区的来源标识执行查询。**复制是整体复制**：源连接若带有环境选项（只读、SSH 隧道），这些选项必须一并复制到新连接，不得只复制连接串而丢掉用户的安全设置。
- R39. 环境名支持非 ASCII（如中文「线上」「测试」）：显示与存储保留原名，而用于来源标识的环境段必须**唯一且稳定**——不同中文环境名不得解析到同一个来源；纯 ASCII 名的既有来源标识保持不变。**唯一性是强制的，不只是「不同中文名」**：大小写不同的名字（`prod`/`PROD`/`Prod`）、仅符号不同的名字（`!!!` 与真名 `env`）以及超过 64 字符上限、只在第 65 字符起才不同的名字，都不得共用同一个来源标识——共用会让该工作区的连接全部变成「有歧义、无法解析」。做法是：只有「规范化后的名字本身就是它的 ASCII 短名」时保留可读句柄，其余在可读前缀后追加短哈希。**长度上限造成的存储键冲突必须在写入时拒绝**（给出可操作提示、零写入、不得静默合并两条连接）；`{confirm:true}` 也不能绕过。
- R40. 环境可改名（模型可调、界面可改）：改名只更换名字，连接与凭据原样保留、无需重新输入；目标名已存在时必须先经用户确认（该操作会覆盖目标环境的连接）。
- R41. 配置目标必须明确：显式给出的工作区不存在时应报错并列出可用工作区，不得静默改用其他工作区；未给出工作区时以当前会话工作区为准，无法确定时应要求明确指定。

## 十、配置页与桌面端承载（dsh 最低版本 0.2.1）

- R42. 配置页必须可通过**设置**进入：插件在设置面板注册一级页面（设置 → DBHub 数据库工具），该承载位属核心界面、任何部署都存在，用户也在此寻找连接管理；同时在官方「插件」页按当前 dsh 版本提供的单插件配置槽位（0.1.6 起为 `<包名>#<行 id>` 的配置页）再挂一份。三处进入的是同一个页面与同一份状态。
- R43. 插件另提供**侧边栏快捷入口**，其显示由**两个条件同时成立**决定：插件处于启用状态，**且**用户在设置条（设置 → DBHub 数据库工具 → ⚙ 设置）里打开了「在侧边栏显示入口」开关（默认开启，随其他选项持久化）。任一条件不成立即隐藏，改动即时生效、无需重启或刷新。
  - **「隐藏快捷入口」与「禁用插件」是两件事**：关掉开关只是不显示入口，插件继续工作、模型仍可正常使用工具；禁用插件则一律不显示入口——禁用中的插件不贡献任何侧边栏入口。
- R44. 侧边栏入口的显隐（无论是被上述开关关闭，还是因插件禁用而消失）**不得**造成自锁——设置页与插件页入口必须始终可用，用户必须能据此重新打开开关或启用插件；官方槽位变化或缺失（如 dsh 升级移除旧槽位）同样不得导致配置页不可达。
- R56. 插件只支持 **dsh >= 0.2.1**（含预发布；0.1.x 与 0.2.0 一律不支持）。配置页数据通道固定为插件自己的 `connection.fetch` 桥（`/api/dsh-dbhub-live/*`），不再探测或依赖已删除的宿主接口（settings 命名空间 / 浏览器侧 `settingsScope`），因此不会因等待一个永远不会出现的服务而静默失活（配置页/侧边栏/插件页入口全部消失且无报错）。宿主版本低于 0.2.1 时，插件**不得**变成空白或拒绝工作：必须在卡片上显示一条中英双语提示（写明最低版本与当前版本），工具、连接与设置照常可用。
- R57. 新增通道不得削弱既有安全边界：浏览器↔宿主的状态读取只承载元数据（延续 R3/R4），连接串只在写入方向从浏览器直达宿主；写入路由必须与 dsh 自身的接口鉴权一致（未鉴权的请求必须被拒绝），不得因为"插件自有路由"而绕过鉴权。
- R58. 插件选项（自动更新间隔、**在侧边栏显示入口**）必须持久化，并且升级插件不得静默重置用户已保存的值（prefs.json 是唯一的用户层，Config 写入回落到同一份值）。这些项同时作为插件的声明式配置暴露（`updateIntervalDays` / `showSidebarEntry` / `announceAccessPolicy`）：可经 `cordis.patch.yml` 或官方插件表单设置，且**与插件自有配置页共享同一个有效值**——任一处的改动都必须在另一处立刻可见（不得出现"改了表单但页面不变"或反之）。侧边栏开关只决定入口显隐，不改变插件的启用状态（见 R43）。
- R73. **桌面端安装与维护路径**：插件必须同时在 **web profile 与 desktop profile** 上可用，两个 profile 的安装/卸载都支持 CLI（`dsh plugin --profile web|desktop add|remove dsh-dbhub-live`，无 dsh 时用 npx 前缀）。桌面端还必须能**全程经可视化「插件」页**完成：左侧菜单 → 插件 → 新增 → 输入 `dsh-dbhub-live`（或从插件市场搜索）→ 安装；安装/更新/卸载都不依赖命令行。同一插件在两处的能力与界面一致。**升级/重装/卸载不得丢失连接与凭据**：数据位于 `$DSH_HOME/storages/dsh-dbhub-live`，与模块目录无关（延续 R23/R25）。
- R74. **三套响应式布局（同一组件、能力等价）**：配置页必须按承载位与实测宽度渲染三种布局：
  - **弹窗模式**（设置 → DBHub 数据库工具，原承载位）：窄列，密度与既有布局保持一致；
  - **宽屏整页模式**（左侧菜单的 DBHub 入口、插件页该行的「配置」）：整页宽列，页头显示插件名与当前版本，设置项在页面内直接可见；
  - **手机浏览器小屏**（宽度 < ~700px）：纵向堆叠的紧凑布局，控件按触摸尺寸排布。

  三种布局下的数据、权限与安全语义必须一致，任何布局都不得显示密码或完整 DSN（延续 R3）。
- R75. **版本展示与更新检查（页头）**：页头必须显示插件名与当前版本（版本为低调小字）。检测到更新时**不得使用报错语义**（红底、红框、error 色），只出现一行低调的「**↑ 可升级到 <latest>**」文字链接；**点击才展开**中性说明面板，面板内含可直接安装的包规格 `dsh-dbhub-live@<latest>`（点击复制）、按部署方式给出的可执行更新指引（**Web**：`dsh plugin --profile web up dsh-dbhub-live@<latest>` 后重启 `dsh web`；**桌面端**：在「插件」页卸载后重装最新版本，配置/凭据保留，见 R73）以及更新说明链接。页面提供图标式「检查更新」入口，并在页面打开时自动检查一次（必须节流，不得每次打开都请求网络）。检查源以 **npm registry 为主、GitHub Releases 为兜底**；失败只作为提示，不得影响插件任何功能。发布说明以 GitHub Releases 为准。
- R76. **设置项位置与控件形态**：宽屏页必须承载完整设置区（与弹窗模式**同一有效值、同一写入口**，延续 R58）：**插件启用/停用**、**dbhub 自动更新间隔(天)**、**侧边栏入口 显示/隐藏**、**向模型注入数据库访问策略**。设置区必须收成**一行紧凑设置条**（标签与控件相邻，不出现"标签在左端、控件在右端"的大段空白）；**宽屏页、插件页以及窄桌面窗口都必须保持横排**（窄列可隐藏状态词/标题并压缩间距，但不得退化为竖排列表）；只有弹窗与手机使用紧凑设置行。字号与控件必须**弱化**（不得抢占连接列表的视觉主体）。控件使用 DSH 原生开关（跟随主题/皮肤）并配**两字汉字状态词**（启用/停用、显示/隐藏、开启/关闭，不得使用"已启用/已开启"这类歧义写法）；「自动更新间隔」的输入框、单位与保存必须在同一行内，不得换行。弹窗模式里同一批设置收在状态行的「设置」折叠里，展开后与宽屏同一形态。
- R77. **连接行内只读开关（所有布局）**：三种布局（弹窗 / 宽屏 / 手机）下，每个连接的只读开关都必须直接出现在该行**数据源旁边**，可就地即时切换，不再需要打开编辑表单；只读的权限不对称不得改变（模型只能开、不能关，延续 R59/R69），且只读状态的标识在所有布局下都可辨认。编辑表单里的勾选可保留，但不得是唯一入口。只读 chip 必须用**开锁 + 「可写」/ 闭锁 + 「只读」**两种状态（同一线性图标风格），不得只靠颜色或灰字区分，否则首次使用者会把可写连接误认为只读。**连接串本身不得带锁形图标**（避免被误读为"需要密码"，也与只读锁语义冲突）——锁只用于表达只读。
- R78. **DSH 版本门槛（最低 0.2.1）**：上述版本/更新入口与三套布局自插件 **5.2.0** 起提供，并且只支持 **DSH 0.2.1 及以上**（含 0.2.1 的预发布版本；0.1.x 与 0.2.0 不支持）。宿主版本低于门槛时**不得**渲染半套界面、变空白或拒绝工作：卡片必须显示一条中英双语提示（最低版本 + 当前版本），工具、连接、设置与桥接照常。环境要求文案与支持矩阵必须说明「最低 0.2.1」；矩阵里不得出现低于 0.2.1 的 target。
- R79. **设置页信息层级**：状态行只显示「运行状态 + 连接数量」，不得在首屏展示工具数量、"固定"模式、部署类型等实现细节；这些内容与长段说明统一收进默认收起的「说明与技术详情」折叠区（深度用户可展开）。设置页首屏应以"一眼知道能操作什么"为准。

## 十一、配置页布局与空间占用

> 本节由 4.2 迭代沉淀：连接数量增长后，原「每个连接三到四行 + 常显添加表单」的平铺列表把大量高度花在重复的工作区标题与固定块上；下列要求把列表改为按工作区组织、每连接一行。

- R45. 连接列表必须**按工作区组织**，并在两种呈现间自动选择：**所有工作区都恰好只有一个环境**时使用**平铺**（一格一个工作区，信息全露、无需展开）；**任一工作区有多个环境**时使用**按工作区分组**。判定只取决于"是否存在多环境工作区"，不引入数量阈值。
- R46. 工作区分组必须支持**点击组头展开/折叠**，组头显示该工作区的环境数与已保存数；分组以**工作区路径**为身份（同名工作区是不同目标，不得仅凭标题合并，同名时必须可见地消歧）。
- R47. 默认展开态：单个工作区自动展开；多工作区时展开**用户最近使用的工作区**，其余折叠；无法判定最近工作区时全部折叠。必须提供「全部展开 / 全部折叠」总控。用户的展开/折叠选择在同一次页面会话内保留（跨重挂载有效），**不跨刷新持久化**。
- R48. 列表中**每条连接只占一行**：环境名、连接元数据（类型/主机/端口/库名）与操作；`source` 句柄不得再单独占据整行，改为**可复制入口**（保持可复制性，且必须让人看得出复制的是 source 句柄而不是整行连接信息）。**库名必须始终可见**：窄行下可截断主机/端口前缀，不得把库名截掉。行内操作以图标承载（必须带 `title`/`aria-label` 说明），不得用文字按钮占掉行宽。**连接的「来源」（手填/扫描/复制/自动发现）不得作为行内徽章常显**——它对绝大多数行都一样，却会抢走行的视觉焦点；应改为按需查看（悬浮提示），其中「自动发现且未持久化」这一例外需明确提示（该条尚未保存）。列表内不得出现密码或完整 DSN（延续 R3）。
- R49. 低频内容必须收拢：状态与开关收成页面顶部一行，自动更新间隔与**「在侧边栏显示入口」开关**（默认开启）一起放进默认收起的设置条（**宽屏模式下改为页面内直接展开的设置区，见 R76**）；**添加连接表单默认收起**。分组内新增连接必须自动带入该工作区（不要求用户重复填写/选择工作区）。关闭该开关只影响侧边栏入口的显隐（见 R43），不影响插件的启用状态与工具可用性。
- R50. 界面配色必须使用 DSH 主题令牌，随主题/皮肤与**半透明背景**自适应：样式表中不得出现不透明色字面量（含兜底值），正文与操作文案的对比度不得依赖固定浅灰。用户可能安装主题/皮肤插件覆盖或省略令牌，此时界面仍需可读（表面继承页面背景而不是涂上白块）。
- R51. 工作区分组与其环境行之间必须有**可见的层级区分**（缩进、引导线、边框或阴影等），不得让组头与环境行看起来是同一层。
- R52. 界面写入连接时，若目标工作区的目标环境名**已经存在**（新增落到已存在环境，或改名落到已存在环境），必须**先提示"将覆盖该连接"并要求用户确认**；取消则不得产生任何写入，并保留用户已填内容以便改名。判定必须使用与宿主一致的环境名规范化规则（去控制字符、trim、空值→`default`、限长），否则会出现"看起来不同、实际是同一个键"的漏判。仅修改**同一个环境**的连接不属此列（那正是编辑的目的，不需二次确认）。**例外：长度上限截断造成的撞键不得当成"覆盖已有环境"**——两个不同的长名截断后会指向同一行，确认覆盖就等于静默丢掉一条连接；必须拒绝该写入并提示名称过长（零写入，`{confirm:true}` 也不能绕过），用户可改用更短的名字，或用截断后的名字更新那条已存在的行。
- R53. 界面操作的**结果必须即时可见**：新增/删除/改名/连接测试提交后，列表不得等到"重新扫描全部工作区"才更新，也不得出现"先整块消失、稍后再出现"的空窗。理想顺序是：宿主应用写入后立刻按已知状态回推，再以权威扫描校正（扫描失败时保留最后一次可用列表）。**失败同样必须可见**：写入被拒（HTTP 非 2xx、`{ok:false}`、网络拒绝）时界面必须渲染一行错误提示（含宿主已清洗的原因或本地化文案），**不得**继续显示"已保存"，且不得把失败当成成功清掉用户的操作；再次点击即重试。读取插件状态失败时必须显示错误行 + 重试入口，不得静默渲染成"没有连接"。**删除是不可撤销的写**，必须先经确认卡；取消则零写入。只接受合法输入的字段（如自动更新间隔：0–365 的整数天）必须**在发请求前**校验并就地提示，非法值不得被当成 `0` 或小数写入。
- R54. 从界面复制连接信息（连接串标签等）必须得到**可直接使用**的字符串：不得因为渲染分层（例如把类型/主机段与库名拆成两个盒子）而混入空格、换行等分隔符。
- R55. **连接发现不得被单个工作区拖死**：自动发现（mise env / .env）的每一次外部探测都必须在有限时间内返回（超时即放弃该工作区的自动发现，不影响其他工作区与已配置连接），且同一目录的结果在短时间内可复用（避免每次列表/执行都重新探测）。**界面显示连接与模型侧看到连接必须一致**：卡片写入所用的工作区标识必须与发现/查询所用的同一份注册表，不得出现"设置里有、模型列不出来"。
- R68. 并发的发现与解析必须**在途去重**：同一时刻只跑一趟工作区扫描（卡片发布、模型列源/执行与连接测试同时落下时共享同一在途结果），同一目录的自动发现解析同样共享在途结果；**共享的失败不得被缓存**——一次失败之后的下一次调用必须真实重试。显式重扫是唯一例外，且必须真的重新扫描。

## 十二、环境选项与上游能力门槛

> 本节由 5.1 迭代沉淀：只读与 SSH 隧道都是**环境级**（工作区 × 环境）的连接属性，交给 dbhub 自身的原生能力执行；插件不自行判定 SQL 是否可写、也不自建隧道实现。

- R59. 支持按环境开启**只读模式**，且只读必须由**上游（dbhub）原生拒绝**写操作来保证（返回 `READONLY_VIOLATION` 一类明确错误），不得以插件自制的 SQL 分类替代上游判定（避免与上游语义漂移、绕过面扩大）。只读是**逐环境**属性，不是插件级全局开关（"整体关停"由禁用承担）。**模型可以开启只读、绝不能关闭**：关闭只读必须由用户在配置页执行（否则模型等于自行提权），模型尝试关闭时应被拒绝并给出指引；界面上必须能看到哪些环境处于只读。开启只读不得使该环境的只读能力（如对象搜索）失效。只读环境放行的语句集**完全以上游为准**（MySQL 实测为 `select`/`with`/`explain`/`show`/`describe`/`desc`，其他连接器略有不同），插件不得自行判定、增减或改写这份白名单。
- R60. 支持为环境配置**手动 SSH 隧道**：主机、端口、用户、认证方式（密钥 / 密码）、密钥路径与口令、可选的**单跳** ProxyJump；隧道由 dbhub 原生能力建立，插件只负责收集、落库与传递。**隧道凭据（SSH 密码、密钥口令）只能由用户在界面输入，绝不进入模型上下文**；模型只能提供/修改非密字段（主机、端口、用户、认证方式、密钥路径、ProxyJump）并可解除隧道。编辑时秘密字段**留空表示保持原值**，已存秘密不得回显；已存的**密钥路径**同样不回显（编辑态只提供"密钥是否就位"这类布尔状态），避免把宿主侧的文件路径带回浏览器。隧道只支持**单跳**：多跳跳板机、`ProxyCommand`、ssh-agent 不予支持，命中时必须明确报"不支持"并给出指引，不得静默降级。插件**不复用也不读取**任何其他插件（包括 DSH 自带的 SSH 工具）的 SSH 配置。
- R61. 连接测试必须验证**有效连接**：即该环境在开启只读 / 配置隧道之后真正会被执行使用的那套连接（包含隧道与只读组合），而不是只测裸连接串；测试结果只是一次性反馈，不得改变连接状态、不得影响其他环境。测试取"待测连接"时**不得为此重扫全部工作区**：已保存的环境直接读持久化的连接，界面上已展示的环境用当前显示的那一行，只有从未扫描到的环境才做一次真实发现；测试进行中必须让等待**可感知**（显示已耗时）。宿主侧的探测预算必须严格低于浏览器侧的兜底等待（无隧道约 25 秒 / 有隧道约 45 秒，对应界面兜底 30 秒 / 60 秒），避免界面已超时而宿主仍在跑。显示已耗时的计时器**只在有探测在途时存在**：空闲页面不得保留任何计时器或轮询（残留计时器会让界面永不空闲）。
- R62. **dbhub 能力门槛**：只读与 SSH 隧道依赖 dbhub **1.4.0 及以上**的原生配置能力；低于 **1.0.0** 的版本必须**明确拒绝**（那条版本线还没有这些配置方言），**1.0.0–1.3.x** 放行但必须给出"未实测"警告，让用户知道风险所在。检测到版本不满足时必须给出**明确错误与升级指引**（升级 dbhub，或改用插件自动安装的版本），**绝不静默降级**——尤其不得退回会被上游静默忽略的旧写法，否则会出现"看起来开了只读、实际仍可写"的危险状态。版本无法判定时放行，并在真实失败时给出指引；不满足门槛时配置页应禁用相关控件并说明原因，而不是等用户操作后才失败。
- R63. 自动发现的环境（未持久化，来自 mise env / .env）在被**显式**设置环境选项（只读 / SSH）时，必须把它**提升为持久化连接**（以当时解析到的连接串落库）并同时写入选项，且必须**明确告知用户**这次提升（此后该环境不再随源文件变化）；提升只能由用户或模型的显式操作触发——列出来源、执行查询、发布状态本身都不得触发持久化。
- R64. 必须提供**独立的 SSH 层连通性测试**（配置页行编辑器的「高级：SSH 隧道」区内、与「测试该配置」并列的「测试 SSH 隧道」），让用户能判断失败出在隧道还是数据库，并**如实说明它能证明什么、不能证明什么**：
  - 先拒绝不完整的隧道配置（缺主机、缺用户或缺凭据时不发起探测，直接说明缺什么）；**但「认证方式 = 密钥 + 密钥路径留空」不算缺凭据**：它按 SSH 客户端惯例落到默认身份文件 **`~/.ssh/id_ed25519`**（即该字段占位符显示的同一个值，插件侧常量 `DEFAULT_SSH_KEY_PATH`）。该默认**只作用于密钥认证且路径为空**：字段填了路径绝不覆盖，密码认证不受影响；「留空 = 保持原值」对秘密字段（密钥口令 / SSH 密码）与已存密钥路径照旧生效（已存路径存在时不会套用默认）。**保存与测试必须用同一条规则**——否则会出现"测试通过、保存却把隧道静默丢掉"，这正是修复前的现场。探测结论里必须**写明这次实际尝试的路径**（附一句"未填密钥路径，已按默认 … 尝试"），避免用户去猜是不是少打了一个字符。**诚实边界**：默认文件在那台机器上可能并不存在，此时结论应是可执行的 `SSH 密钥文件不存在或不可读：~/.ssh/id_ed25519`（并带同一句说明），而不是含糊的"配置不完整"；
  - 先做 **TCP 可达性**探测（插件宿主 → `ssh_host:ssh_port`，约 5 秒预算），给出「主机不可达 / 端口未开放」的明确结论并附**套接字错误码**（ENOTFOUND / ECONNREFUSED / ETIMEDOUT 等）——这一步单独就能把"DNS / 防火墙 / 端口"问题与其他问题分开；
  - 密钥认证时另做本地检查：私钥**文件存在且可读**；
  - 然后**故意**让 dbhub 对一个不可能在监听的地址（`127.0.0.1:1`）建立隧道，并**按证据判定，顺序固定且不得颠倒**：① 报错里出现 **SSH 层特征**（`SSH connection error` / `__dbhubSSHTunnelError` / 认证方式全部失败 / 私钥无法解析 / 加密私钥缺口令 / 握手 / ProxyJump / ssh2）时**单独即可判定隧道这一层断**（这类特征只会由隧道级问题产生）；② 否则出现 **数据库层特征**（`PROTOCOL_CONNECTION_LOST`、`Connection lost`、`server closed the connection`、`Access denied`、`Unknown database`、`ER_*`、`ECONNREFUSED`/`ECONNRESET`/`ETIMEDOUT`/`EHOSTUNREACH`、`SSH tunnel closed`）时判定**隧道可用**——驱动只有在转发连接建立之后才会说话（`SSH tunnel closed` + `Connection lost` + `PROTOCOL_CONNECTION_LOST` 正是"隧道通了、隧道后面的库不可用"的形状，且**不会**指名转发目标，所以"是否指名目标"不能作为唯一证据，这正是曾经的误判现场）；③ 否则若报错**指名了转发目标**，同样判定隧道可用；④ 两者都没有时才如实给「SSH 层结果无法判定」并附输出末尾，**不得猜测**；<!-- desensitize:allow （`__dbhubSSHTunnelError` 是 dbhub 自己的错误属性名，不是凭据） -->
  - **诚实边界（必须写明）**：该测试证明的是"网络可达 + 本地密钥就位 + SSH 层能否起来"，**不是**一次带真实数据库的完整 SSH 会话验证；隧道能建立不等于隧道后面那个库一定连得上（那仍由 R61 的有效连接测试回答）。
- R65. 连接测试失败时的**诊断必须分层归因，且只取 dbhub 输出的末尾**：
  - 诊断保留 dbhub 输出的**尾部**（多行、约 600 字符、保留换行原样展示）——致命行在输出的末尾，只取开头（如 dbhub 的启动横幅）会把真正的错误截掉，用户就看不出失败原因；尾部必须**丢掉栈帧行及其折行残片**（`    at …`，以及以 `file.js:L:C)` 结尾的续行），并按**行边界**截断：宁可少几个字符，也不得让消息以半行/半段路径开头（从半行开始的诊断读起来像乱码，也会让人误以为消息被截坏了）；
  - 配置了隧道时，消息前必须标出失败的层：「【SSH 层】隧道未建立：…」或「【数据库层】隧道可能已建立，失败发生在数据库连接/认证：…」；后者必须**措辞谨慎**（只能说"可能"），因为只有 R64 的独立测试才能证明隧道确实起来了；插件自身无法启动 dbhub / 生成配置时另用「【插件层】…」前缀（该情形既不属于隧道层也不属于数据库层）；同时必须给出可操作结论：**报【数据库层】即表示失败出在隧道后面的数据库（隧道这一层没有报错），用户不必再怀疑 SSH**——要把"可能"钉成确定结论，由 R64 的独立测试回答；
  - **用户名与密码都不得出现在诊断中**：dbhub 自身的横幅打印只掩了密码的 DSN（`mysql://user:****@host:3306/db`），因此清洗必须把**任意 URL 形态连接串的整个 userinfo** 折叠掉（`scheme://user:pass@host` 与 `scheme://user@host` → `scheme://****:****@host`），使诊断呈现为 `mysql://****:****@host:3306/db`。这是既有零知识契约的实际执行：密码与用户名不仅不得进模型上下文（R3），也不得出现在配置页的诊断文本里。
- R69. 只读的**拦截点与解除能力必须分离**：模型侧"只能收窄、不能放宽"的约束只落在工具/模型路径上——宿主与存储层必须保留完整的关闭能力，用户在配置页必须真能关掉某个环境的只读（把拦截下沉到存储层会让只读变成永久无法解除，用户再也关不掉自己设的限制）。
- R84. 支持按环境设置**结果行数上限**（`maxRows`），并支持**单次执行主动覆盖**它：
  - 环境级取值：`0` 或缺省 = 不限（存量连接的行为与结果必须**逐字节不变**），`N>0` = 每条语句最多 N 行；调整在界面进行（连接行的「高级」区域，数字输入，占位提示「0 或留空 = 不限」），**非法值（负数、非整数、NaN、非数字文本）必须就地报错且零写入**，不得被静默取整或当成"不限"。
  - 裁剪由插件在宿主侧对结果做（dbhub 的 `max_rows` 是静态 TOML 配置，无法表达单次上限）：被截断的语句必须**显式标注**（`truncated` 与 `shown`）并保留原始行数计数（`count` 原样保留），只裁行数组、不得改变行数据的形状。
  - **提示必须显式**：结果首行给出一条本地化提示，写明本次上限、每条被截断语句的原始行数，以及「本次可用 `maxRows` 覆盖」。
  - **失败必须安全**：结果不是预期的 JSON 或结构不符时**原样返回**，不加提示、不破坏内容——裁剪永远不能把一条好结果变成坏结果。
  - **单次覆盖参数**：`dbhub_execute_sql` 接受 `maxRows`（整数；`0` = 本次完全不限，省略 = 用环境设置）。优先级为**调用参数 > 环境设置**；该参数只用于本次裁剪，**绝不透传给 dbhub**，也不改变环境保存的值。
  - 环境值本身无效（手工改坏的文件）时按**不限**执行，不得让该环境的所有查询变成一行或直接失败。
- R86. SSH 隧道的秘密（登录密码 / 密钥口令）必须保存在 **DSH 的凭据库**（`ctx.get('credentials')`，默认 `$DSH_HOME/.credentials.yaml`，由 DSH 管理；插件不得自行读写该文件），插件自己的连接文件 `credentials.json` 只保存**引用名**（`ssh.passwordRef` / `ssh.passphraseRef`，形如 `DSH_DBHUB_SSH_<8–12 位小写十六进制>`，随机生成、与工作区/环境名无关）：
  - **写入顺序是安全属性**：任何把秘密写进 store 的路径（配置页 add / set / options、模型 `dbhub_configure`、`copyFrom`）都必须先 `creds.set(ref, value)` **成功**，之后 store 才允许只存 ref。凭据服务不可用或写入抛错时**保持既有明文布局**（连接不受影响）并只警告一次，警告文案不得含值或路径。
  - **读取必须重新解析**：执行与探连前用 `resolveEnvSecrets` 把 ref 异步解析成真值（每次操作重新调用，**不缓存**）；明文不得进入任何返回给浏览器/模型的 view 或 patch。ref 存在但取值失败（例如凭据文件被删）必须明确报「该连接的口令已不在凭据库里，请在卡片里重新输入」，**不得按空口令继续**（那会伪装成 SSH 认证失败），且不得 spawn dbhub。
  - **迁移幂等**：老版本遗留的明文行在启动时一次性搬进凭据库（已有 ref 的行直接跳过，重复运行不产生新 ref、不重复写入）；迁移失败（凭据服务不可用 / `set` 抛错）时保留明文、不破坏现有连接、只警告。
  - **生命周期**：删除行后若其 ref 已不再被任何行引用则释放（best-effort，失败只警告）；`copyFrom` 与源行**共用同一个 ref**（不复制秘密）；`rename` 不改变 ref。
  - **「留空 = 保持原值」语义不变**：秘密字段留空时不覆盖 ref、也不 unset。

## 十四、模型侧数据库访问策略（提示词约束）

> 本节沉淀一次生产事故的教训：只读的**执行点**在 dbhub 内部，因此只约束"经过本插件"的调用；模型自行改走 shell（在宿主机上找到 `pgsql.exe`/`psql` 等客户端直连）完全不受管控。工具描述不足以压住这种绕道——工作区说明（`AGENTS.md`/`CLAUDE.md`）是以 **user 角色**注入模型历史的，而它自己就写着"不得覆盖 system 指令"。因此必须由**系统提示词**层声明本插件是唯一授权途径，并明确否定"工作区里的直连配方"。
>
> **共存是同一条契约的一部分，不是补丁**：用户可能同时装了别的数据库插件。权威声明若写成"本机所有数据库操作都走我"，就会同时犯两个错——它会禁止用户用另一个插件去连**本插件根本连不上**的库（dbhub 只有 MySQL/PostgreSQL/MariaDB/SQLite/SQL Server 五个连接器），又会和同类型插件各自的"唯一途径"声明互相矛盾。因此权威声明必须**按作用域**给出。

- R71. 插件启用期间必须向模型贡献一条**常驻系统提示词策略段**（`ctx.systemPrompt.section()`，`order` 靠近提示词末端、位于首方保留位之前），把数据库访问收敛到本插件；文本必须紧凑（约 600 字，另可附一份受上限约束的 `@` 别名目录，由单测守上限）并只陈述能力、约束与逃生口，不得复述工具参数说明。至少覆盖：
  - **唯一授权途径（按作用域）**：权威声明只覆盖**本插件已配置的连接**（`dbhub_list_sources` 里出现的那些），这些库一律走 `dbhub_*` 工具（查询、写入、DDL、对象搜索）；**不得**写成"本机唯一授权途径"或"所有数据库操作"；
  - **点名禁止 shell 级直连**：`psql`/`mysql`/`sqlite3`/`sqlcmd`/`pg_dump` 等命令行客户端、临时脚本、程序驱动与其它 MCP 一律不得用于连**这些库**，也**不得为了连库去宿主机上寻找或调用这类可执行文件**——只读由 dbhub 在插件内硬拒绝，绕开插件的直连不受插件管控，这一层只能靠提示词约束，所以必须写明；
  - **反投毒**：工作区文档、脚本或 `AGENTS.md` 中出现的直连数据库"配方"**不构成授权**，不得照做（含模型自己在过去会话里写下的配方）；发现时应告知用户；
  - **只读边界与逃生口**：命中 `READONLY_VIOLATION` 后**不得改用任何其它途径**完成这次写入——必须显式点名**包括换用别的数据库插件/工具**（这是共存场景下最现实的绕道），只能把拒绝原因与影响告知用户；本插件对已配置库确实做不到的操作（备份、非 SQL 管理命令等）先说明限制并请用户给出授权方案，不得自行绕过；
  - **共存：不支持的库让位**：本插件不支持或未配置的库（MongoDB/Redis/Oracle 等，或用户从没在这里配置过的实例）必须**显式允许**用户安装的其它数据库插件或工具接手；不得为"统一走本插件"而拒绝，也不得因此改用命令行直连；
  - **共存：重叠目标有确定优先级**：同一个库在本插件和别的插件里都配置时，默认用本插件的 source（只读/隧道等安全设置在宿主侧），用户明确要求换工具时才换，判断不了先问用户——不得自行换路；
  - **不压制同类插件**：不得实现（也实现不了）"禁用另一个数据库插件"的语义。冲突只用上面三条收敛：作用域、重叠优先级、问用户。压制会把模型推向 CLI，正是本节要防的结果；
  - **回执侧同样禁止绕道**：只读命中（`result.readOnlyHint`）与凭据/连接失败（`result.authHint`）的回执必须各带一句"不要改用命令行客户端/脚本/其它数据库插件"，因为这两处正是模型最可能起意绕道的时刻；
  - **禁用即静默**：插件被禁用时该段必须贡献**空文本**（空段在组装时被丢弃），绝不能出现"提示词声称 dbhub 是唯一途径、每次调用却回 `result.disabled`"的自相矛盾；
  - **可选依赖、绝不致命**：注册必须经 `ctx.inject(['systemPrompt'], …)` 并挂在 effect 作用域上——同名段在同一作用域重复注册会抛错，而 `apply()` 会在 reload 时重跑；部署没有该服务时只是不注入（老版本 dsh 自动降级到工具描述这一层），不得因此启动失败；
  - **零知识与插值安全**：文本不得含真实形态连接串，也不得含未注册的 `{{变量}}`（严格插值会让整次提示词组装失败）。
  工具描述侧只允许在**动作点**补一句最短禁令（`dbhub_execute_sql`，即写入最可能发生的地方），四份工具描述不得重复整段政策（同一事实只说一次）；该句同样必须按作用域写，并说明不支持的库用其它插件。
- R72. 策略段的注入必须由**用户开关**控制，且**默认开启**：
  - 选项 id `announceAccessPolicy`（布尔），走既有三条通道（`prefs.json` 持久化落点、`Config` 的 volatile 字段供 cordis.yml/profile patch 固定、设置条复选框即时生效），客户端以「立即生效、无需保存」的语义写回（与 `showSidebarEntry` 同款），并只在设置条的 tooltip 里解释语义；
  - **关闭只影响那段文字**：工具、只读、隧道、连接管理一律照常；关闭后该段返回空文本（空段被丢弃），系统提示词保持干净；
  - 默认开启的理由：本插件的定位就是"装了就该优先用它"，而策略段是唯一能压住工作区直连配方的层；不默认关就不会出现"用户以为在保护、实际没注入"的落差；
  - 开关状态必须与插件启用状态**取交**（任一为否即不注入），且不得写进任何"能力开关"的语义里（它不是禁用插件，也不是关闭只读）。

## 十五、输入框 `@` 数据源引用（一条消息可多选）

> 用户原话：「我想要的是会多次选择，例如帮我在这个库里 `@xxx数据源` 查下某某关联表在 `@xxxx数据源` 里」。因此引用的**最小单位是一条消息里的多个标记**，每个标记各自落到自己的库上。

- R80. **输入框 `@` 菜单提供 DBHub 分组**：用户在消息输入框打 `@` 时，菜单里必须出现本插件的连接分组，每个已配置连接一行（别名 + 工作区 + 元数据标签；只读连接带只读标记）。选中插入一个与 `@文件` 同形态的**可视引用标记**；**同一条消息可以连续插入多个**，提交时每个标记各自序列化成模型可读文本，互不覆盖。
- R81. **稳定别名（显示与手打用的短名）**：每条连接必须有唯一、非空、不含空白与 `@` 的别名，且对同一组连接**确定性**生成（与扫描顺序无关）：环境名在所有工作区里唯一时就用它，否则 `<工作区>_<环境>`，仍撞名再追加 `-2`/`-3`。别名只在宿主侧计算一次（客户端与策略段都读同一个值）。**别名不是身份**：真正的身份仍是不可变的 source 句柄，改名/新增/删除连接不得让已插入草稿的标记失效。
- R82. **模型侧可读的标记语义**：提交后的模型文本形如 `@db:<source 句柄>`，由系统提示词策略段解释其含义——按标记出现顺序与请求一一对应、一条消息可有多个、各自落在自己的库上、不要合并成一次查询；策略段同时附一份紧凑的「别名 → 句柄」目录，超过上限时截断并指向 `dbhub_list_sources`。
- R83. **零知识与可选降级**：`@` 菜单候选只能包含别名、工作区标题、连接元数据（类型/主机/端口/库名）与只读标记，**任何情况下不得出现 DSN、账号、密码或本机路径**；插件停用、状态未就绪/读取失败或没有任何连接行时菜单为空（不显示假数据、不抛错）；运行环境不提供输入框触发服务时该分组不出现，工具与配置页一切照常。

## 十六、会话权限模式（写操作的授权闸门）

> 现状问题：插件完全忽略会话输入框的权限模式，用户选「仅可查看」时模型照样能写库；而「环境只读」是另一个属性（用户在配置页设的、持久化到连接行），两者不是同一个东西。本节的闸门**叠加**在环境只读之上，且**只可能更严**。

- R85. `dbhub_execute_sql` 必须**尊重会话输入框的权限模式**，同时**不改变**插件「环境只读」开关的既有含义（仍是 dbhub 的硬拒绝）：
  - **组合语义**：环境只读**开启**时行为完全不变（仍由 dbhub 拒绝并给出「需用户在设置里关闭只读」的引导，会话闸门不介入）；环境只读**关闭**时——会话为「仅可查看」→ **本地直接拒绝**（不 spawn dbhub、不写临时配置、不写 store）；「工作区内修改」→ 写语句**每次弹窗授权一次**（只有 `allowed-once` 算授权），读语句不弹窗也不打扰；「完全权限」→ 直接执行。
  - **写判定必须保守**：剥掉前导空白与注释后按顶层 `;` 拆分语句（`'…'`、`"…"`、反引号与注释里的分号不算分隔；`\'` 与 `''` 转义要处理）；每条取首关键词，`SELECT`/`SHOW`/`DESCRIBE`/`DESC`/`EXPLAIN`/`VALUES`/`TABLE`/`PRAGMA` 为读，`WITH` 需向后扫过配平括号找到主语句、且主语句是 `SELECT` 才算读，其余一律为写。**任一条为写则整次调用按写处理**（`SELECT 1; DROP TABLE t` 必须是写）；空输入/只有注释按读处理（dbhub 自己会报错）。宁可误判成写（多弹一次窗），也不得把写判成读。MySQL 可执行注释（`/*!…*/`）的正文必须参与判定，否则它就是一条真实绕过路径。
  - **闸门失败必须关死**：只有 `allowed-once` 放行；`rejected`/`cancelled` → 「用户拒绝了本次写入」的本地化拒绝；`unavailable` → 「当前会话不允许弹窗确认（策略为从不询问）」的本地化拒绝；`approval` 服务缺失、或 `approval.request` 抛异常（例如不在开启的轮次里）同样拒绝，并只 `warnOnce` 一次。**拒绝路径不得 spawn dbhub、不得产生临时文件、不得写 store。**
  - **可选依赖、不破坏自动化**：`sandboxPolicy` 服务缺失（无头/SDK 部署）时**不设闸门**，行为与之前完全一致；`resolve()` 抛异常（例如会话 cwd 不可用）同样不设闸门，并且只记一条**不含 DSN/路径**的警告——权限探针坏了不能把所有写入都变成拒绝。
  - **文案边界**：拒绝与弹窗文案均为本地化（中英，en 不含中文）；弹窗只写「source 句柄 + 语句类型 + 语句前 N 个字符（仍过 `scrubSecrets`）」，**不得整段回显语句**（`reason` 还会进会话日志），也不得出现 DSN/主机/账号；拒绝文案必须写明下一步，并禁止改用命令行客户端 / 临时脚本 / 其它插件绕过。
  - **影响范围**：`dbhub_search_objects` 与 `dbhub_configure` 不经过这道闸门；插件「环境只读」的判定仍完全归 dbhub——本闸门只可能更严，绝不放宽 dbhub 的拒绝（与 R59 一致：插件不取代上游判定，只额外收窄）。

## 十七、连接列表的搜索 / 排序 / 批量测试

> 用户原话：「连接搜索 / 排序 / 批量测试。」只关心**用户能感知的体验**：连接一多就要能筛、能排、能一次验完；不引入新协议、不新增持久化通道。

- R87. 连接列表上方必须有一条**搜索框**（占位「搜索连接…」，三种布局 empty / tiled / grouped 都在），按 **工作区标题 / 环境名 / 别名（`alias`）/ `conn` 元数据**做**大小写不敏感的子串**过滤（中文环境名必须可命中）。过滤生效时旁边显示「N / M」（M = 总连接数、N = 命中数）并可**清除搜索**；**无匹配渲染「没有匹配的连接」+「清除搜索」**，不得渲染成「还没有配置连接」（那是"一条都没配"，是不同的事实）。过滤**只影响显示**：保存 / 测试 / 删除的目标仍是用户点的那一行；搜索只匹配既有元数据字段，**不得触碰或请求 DSN**。
- R88. 必须提供**排序**切换（两种就够）：`名称`（默认：工作区标题 → 环境名，确定性、与扫描顺序无关）与 `最近更新`（按 `updatedAt` 倒序，同值回落到名称）。**分组顺序必须跟着排**（不能只排行而组头固定）。排序选择记在组件本地，**不新开持久化通道**。`最近更新` 的时间戳来自宿主已发布的**工作区快照**（行上没有该字段时不发明一个）。
- R89. 列表头部必须有「测试全部（N）」，**N = 当前可见（过滤后）的行数**（筛了 2 条就只跑 2 条），并发上限 **2**；每行显示自己的状态：`等待` / `测试中…` / `通过 ✓` / `失败 ✗（原因截断）`，上方一条汇总「x 通过 / y 失败 / z 未测」。运行中按钮变「停止」：**未开始的回到「未测」，已发出的请求允许自然完成**（协议没有取消，不得伪造取消）。单行测试与批量测试必须使用**同一个** `{op:'test', workspace, env, nonce}` 形状与既有的 30s / 60s 看门狗，失败原因走既有本地化文案（`test.notSent` / `test.timeout`）。
- R90. **不新增协议、不新增轮询**：批量结果直接读每次 `POST /op` 响应里的 `value.testResult`（宿主在应答前已写入本轮结果），按 nonce 关联每一行；**不得**复用单行测试的 view-mirror effect（N 行会互相覆盖），也不得引入定时轮询（批量结束即停）。组件卸载必须清掉所有计时器与在途状态（`check:ui` 有「no poll interval outlives its page」断言）。批量/单行两套状态互不覆盖：批量用自己的 map，单行的 `tests`/`nonceKeys` 只服务单击；两套共用 `testTimers`（按唯一 nonce 键，互不清对方）。
- R91. 验收：`check:ui` `[49]`（过滤与空态、排序后的行/组顺序、并发上限、逐行状态、停止、汇总、卸载无残留计时器）+ `test/conn-list.test.mjs`（纯函数：大小写 / 中文 / 别名 / `conn` / 空查询 / 排序稳定 / 过滤为空）。
## 十八、插件不可用时的自救指引

- R92. /state 读取失败的错误行必须在「重试」之外给一句**可执行的下一步**：去「设置 → 插件」确认这一行处于启用状态；刚升级过版本就重启一次 DSH；并写明「工具本身仍可调用，只有这个面板读不到状态」。理由是插件被 DSH 禁用、或宿主半没加载起来时，**这张卡片是唯一还能说话的地方**，一条光秃秃的"读取失败"没有任何出路。文案走双语字典，check:ui [33] 钉住。
- R93. 写请求被拒后补一次 refresh()：写会领取一个更高的读序号并把先发起的 `/state` 读丢掉（水位线语义），失败时没有后续应答，卡片可能停在 `loading` 直到下一次轮询。一次重读把窗口关掉，且**不得**吞掉写失败（rejection 仍要到达调用方）。

## 十九、数据库口令与 SSH 口令同源（DSH 凭据库）

> 用户原话：「只要是密钥相关都放在 credentials。保存内容不再局限于 dsn 形式，想使用 dsn 连接还是变量连接通过中间层转换就行。」SSH 口令已经搬进凭据库，本节把**数据库口令**也搬进去。存储层仍然是 DSN（dbhub 的 `[[sources]]` 只有 `dsn` 一个连接字段，分项 `DB_*` 模式不能用——会失去只读白名单与 SSH 隧道），所以"变量连接"的转换由插件这个中间层完成：写入时把口令拆出去、每次操作时再拼回来。

- R94. **数据库口令只存 DSH 凭据库，DSN 字段不再含口令**：
  - **拆分（写入/迁移时，纯函数）**：URL 形态 `scheme://[user[:password]@]host[:port]/db?params` 只处理 authority 里的 `user:password@`，**按原始文本切片**（不在 URL 编解码之间来回转），保留 `user@`，口令段（编码后的原始片段）作为凭据值；属性形态（`Server=…;User Id=…;Password=…`、`pwd=`、任意大小写）把口令值原样换成占位符 `${DSH_DBHUB_DSN}`，值进凭据库。存储层新增 `dsnPasswordRef`（`DSH_DBHUB_DSN_<8–12 位小写十六进制>`，与 SSH 引用同款随机命名、与工作区/环境名无关）。
  - **安全闸门**：拆分结果必须能**逐字节还原**成原串（`join(split(dsn)) === dsn`），否则放弃拆分、保持原样，并只警告一次「该连接的密码无法安全拆分，仍保存在本地连接文件里」（不含值/路径）。宁可少拆一条，也不能拼出一条对不上的 DSN。多个不同口令值共处一个属性串、URL 尾部又带 `;password=` 等一个引用表达不了两处的情况同样放弃。
  - **拼装（读取/执行/探连时）**：`resolveEnvSecrets` 每次操作按 ref 取值并还原成完整 DSN，**不缓存**；ref 在但值取不到（或拼不回去）→ 新的本地化报错 `result.dsnSecretMissing`，语义与 `result.sshSecretMissing` 一致：**不 spawn dbhub、不跑探连**，绝不退化成无口令 DSN（那会伪装成认证失败）。
  - **迁移**：boot 的一次性迁移扩展为「SSH 明文 + DSN 口令」两件事，仍然**幂等**（有对应 ref 就跳过）、先 `creds.set` 成功再改 store、失败保留原样并只警告一次。
  - **生命周期**：删除连接时释放无人引用的 ref（与 SSH 同款）；`copyFrom` 共用源行 ref（源行是未保存的自动发现行时才就地拆分）；`rename` 不动 ref；卡片改连接（`{op:'set', dsn}`）重新拆分——新口令进凭据库、旧 ref 释放。
  - **可见性与零知识**：`connLabel` 对去口令的 DSN 输出不变（仍只显示元数据）；`/state` 行不得出现口令，也不得出现比"是否拆不动"更多的细节（只加布尔 `passwordUnsplit`），卡片在既有 tooltip 提示位说明；任何日志/错误/view/patch 都不得出现口令。凭据服务缺失或拆分失败时保留明文（旧布局，连接不受影响）并警告一次。
  - **验收**：`test/dsn-secret.test.mjs`（往返语料逐字节相等、store 文件不含 canary、ref 无值 → 零 spawn、迁移幂等/降级、copyFrom 共用、删除释放、`connLabel` 不变）+ `test/cred-store.test.mjs`。

## 二十、查询结果导出（CSV / JSON）

> 用户原话：「查询结果导出 CSV / JSON。」插件没有「结果卡片」可以挂按钮，所以导出做成**工具参数**；价值在于**大结果不占模型上下文**——落盘后回执只给摘要与路径。

- R95. `dbhub_execute_sql` 接受可选的 `export: 'csv' | 'json'`，把**本次调用**的结果行写成宿主机的本地文件：
  - **命中时回执只给摘要**：本地化的一行（`已导出 <N> 行到 <path>`；多语句逐条列出）＋一句「文件在宿主机上，模型不要再把行内容贴回对话」，**不再内联行数据**；摘要里只有 **source 句柄 / 行数 / 路径**（延续 R3 零知识：不得出现 DSN、主机、账号）。
  - **行数上限**：导出**默认不受环境的 `maxRows` 限制**（导出就是"我要全部"）；**只有调用方显式传 `maxRows`** 时才按它截断，并沿用既有截断提示语义（提示仍是回执首行、`count` 保留原值）。不传 `export` 时行为**完全不变**。
  - **多语句**：csv = **每个 statement 一个文件**（`<base>-1.csv`、`-2.csv`…）；json = **一个文件**装整个 `{source, statements:[{sql, rows, count}], exportedAt}` 载荷（**不含 DSN**）。
  - **CSV 方言**：列集合 = 所有行 key 的**并集、按首次出现顺序**（不排序，保持与数据库列序一致）；`null`/`undefined` → 空串，对象/数组 → JSON，布尔/数字 → 字符串；含 `,` `"` `\r` `\n` 的字段（含表头）按 RFC 4180 双引号包裹、内部 `"` 双写；行尾 CRLF、文件末尾不加多余空行；**默认不加 BOM**（可选参数才加）。
  - **落盘位置与权限**：`$DSH_HOME/storages/dsh-dbhub-live/exports/`（目录仅本账号可访问、文件仅本账号可读写，与连接数据同一约定）；文件名 = `<sourceId 的 ASCII 安全化>-<yyyymmdd-hhmmss>-<seq>.csv|json`，安全化必须**不可能逃出该目录**（没有路径分隔符、`..`、控制字符；超长有上限并用短哈希保唯一）。同名**绝不覆盖**（同一秒的再次导出加后缀）。插件**不自动清理**导出文件；删除该数据目录即全部清空。
  - **失败必须安全（fail-soft）**：写文件失败（权限 / 磁盘）或结果不是文档形状时，**仍按原逻辑返回**（受 `maxRows` 约束的）内联结果，并追加一句本地化「导出失败：<code>，已改为直接返回结果」——**绝不能因为导出失败让一次成功的查询变成失败**。
  - **验收**：`test/export.test.mjs`（CSV 纯函数与转义、列序、空结果、CRLF/无 BOM、文件名安全化、端到端不内联/路径/显式 maxRows 截断/环境上限不生效、写失败 fail-soft、零知识 canary）。
